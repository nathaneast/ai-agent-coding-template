# /cm — Commit (this session only)

**이 대화 세션에서 Claude가 Edit/Write/MultiEdit한 파일들만** 골라서 커밋합니다. 푸시는 하지 않습니다.

## 실행 순서

### 1. 세션에서 변경한 파일 목록 추출
- 이번 대화에서 `Edit`, `Write`, `MultiEdit`, `NotebookEdit` 도구 호출의 `file_path`들을 모두 수집
- Bash로 `git mv`, `git rm`을 실행한 흔적이 있으면 그 파일들도 포함
- 중복 제거하고 절대경로 → 레포 상대경로로 변환

### 2. 변경사항 검증
```bash
git status --short
git diff --stat
```
- 위에서 추출한 파일 목록 ∩ 실제 변경된 파일만 대상으로 한다
- **세션에서 만지지 않았는데 dirty인 파일은 절대 자동 추가 금지** — 사용자에게 보여주고 알려만 준다

### 3. 사용자에게 확인 표시
다음 형식으로 보여준다:
```
📝 이 세션에서 변경된 파일:
- src/foo.ts (수정)
- src/bar.ts (신규)

⚠️ 세션 외 dirty 파일 (커밋 대상 아님):
- README.md (사용자가 직접 수정한 듯)
```

### 4. 커밋 메시지 자동 생성 (사용자 입력 받지 않음)
- **무조건 대화 맥락에서 자동 생성한다.** 인자가 들어와도 무시.
- 이번 세션에서 Edit/Write한 변경 사항 + 사용자와 나눈 의도/목적을 종합해 1줄 요약 (한국어 OK)
- 형식: `<type>(<scope>): <설명>` (예: `feat(auth): 로그인 폼 검증 로직 추가`)
- type: feat / fix / chore / refactor / docs / test / style / perf 중 적절히 선택
- scope: 가장 많이 만진 폴더/모듈 이름 (없으면 생략 가능 → `feat: ...`)
- 변경이 여러 영역이면 가장 핵심 의도 1개로 압축. 부가 변경은 본문 bullet으로.
- 본문이 필요할 만큼 큰 변경이면 한 줄 띄우고 핵심 변경 2~4개를 `-` bullet으로.

### 5. 스테이징 + 커밋
```bash
git add <세션 파일들 명시적으로 나열>
git commit -m "<메시지>"
```
- `git add .` 또는 `git add -A` **금지** (세션 외 변경까지 들어감)
- 파일 경로에 공백 있으면 따옴표로 감싸기

### 6. 결과 보고
- 커밋 해시 (`git rev-parse --short HEAD`)
- 커밋된 파일 목록
- 다음 단계 힌트: "푸시도 하려면 `/cp`"

## 주의사항

- **세션 추적 실패 시** — 도구 호출 기록을 정확히 못 잡으면 사용자에게 "어떤 파일을 커밋할지 모르겠습니다. `git status` 결과 보여드릴까요?" 라고 물어본다. 절대 모든 dirty 파일을 추측으로 커밋하지 말 것.
- **시크릿 점검** — `.env`, `*credentials*`, `*.pem`, `*.key` 같은 파일이 목록에 있으면 경고하고 사용자 명시 승인 받기.
- **pre-commit 훅 실패** — 훅이 막으면 원인을 보고 수정 후 새 커밋. `--no-verify`는 사용자가 명시 요청할 때만.
- 커밋 메시지에 Co-Authored-By 같은 자동 서명 **추가하지 말 것** (사용자 개인 워크플로우).

## 사용 예

```
/cm    # 항상 자동 메시지로 커밋 (인자 받지 않음)
```
